MAKER's solution: Instead of one person trying to cross alone, have multiple people vote on where to place each foot. The majority opinion is almost always right, even if individuals sometimes make mistakes. Plus, if someone seems confused (talking too long, giving weird answers), ignore them!

The Problem: Errors Compound Catastrophically

Here's the fundamental challenge with using AI for long tasks:

The Math of Failure: If an LLM has a 99% success rate per step (which sounds great!), over a million steps, the chance of completing without error is:

0.99^1,000,000 = essentially 0%

Even with 99.9% accuracy per step, you'd expect to fail after just ~1,000 steps.

Real-World Scale Problems

Modern society routinely executes tasks with millions of steps:

  • iPhone production: ~1 billion people contribute across hundreds of suppliers
  • Hospital operations: Thousands of precise steps per patient
  • Tax processing: Millions of calculations at national scale
  • Even baking bread: Dozens of precise steps that must all succeed

Maximal Agentic Decomposition (MAD)

The key insight: break tasks into the smallest possible pieces. Each "microagent" only needs to solve ONE step.

cancel Single Agent Approach

  • One LLM handles entire task
  • Context grows with each step
  • Gets confused by accumulated info
  • One wrong step = total failure
  • No opportunity for error correction

check_circle MAD Approach

  • Each step = separate agent
  • Minimal context per agent
  • Stay focused on one tiny task
  • Each step can be verified
  • Error correction at every step
lightbulb Assembly Line Analogy

Think of building a car. You could have one person build the entire car (they'd get tired, make mistakes, forget things). Or you could have an assembly line where each worker does ONE specific task perfectly, then passes it to the next worker.

MAD is the AI equivalent of the assembly line. Each microagent only needs to be good at one tiny thing.

Why Smaller is Better

Key properties of microagents:
  • Limited context = less confusion
  • Simple tasks = higher accuracy
  • Modular = can verify and correct each step
  • Small LLMs can handle small tasks (cheaper!)
how_to_vote

Error Correction by Voting

Once tasks are decomposed into tiny steps, we can apply error correction through voting. This is similar to how digital communication systems handle noisy channels.

First-to-ahead-by-k Voting

For each step:

  1. Sample multiple answers from the LLM
  2. Count votes for each unique answer
  3. Keep sampling until one answer is k votes ahead of all others
  4. That answer wins!
# Example: Step 42 of solving Towers of Hanoi
# k=3 (need 3 votes ahead to win)

Vote 1: [1, 0, 2] - Move disk 1 from peg 0 to peg 2
Vote 2: [1, 0, 2] - Same answer (2 votes)
Vote 3: [2, 0, 1] - Different answer (1 vote)
Vote 4: [1, 0, 2] - (3 votes, 2 ahead)
Vote 5: [1, 0, 2] - (4 votes, 3 ahead)

Winner: [1, 0, 2] with 3+ vote margin!

The Math Behind Voting

Probability of correct answer after voting:

If p = probability of correct answer per sample, and k = required margin:

P(correct) = p^k / (p^k + (1-p)^k)

With p=0.998 and k=3: P(correct) ≈ 0.999999994

This turns a 99.8% accurate model into one that's effectively perfect!
trending_up Scaling Law Discovery

The expected cost grows only O(s ln s) - that's log-linear!

This means doubling the task size only slightly increases the cost. Compare to exponential growth without error correction, where doubling size would make the task impossible.

Why k=3 is Enough

For a million-step task with 99.8% per-step accuracy:

  • k=1: No error correction, will fail
  • k=2: Better, but still risky
  • k=3: 95%+ probability of solving entire task perfectly
  • k=4+: Even safer, but more expensive

Red-Flagging: Spotting Trouble

The third component of MAKER is red-flagging: detecting and discarding responses that show signs of unreliability.

Two Red Flags

text_fields

1. Overly Long Responses

If the LLM needs 2000 tokens to answer a simple question, it's probably confused and going in circles. Discard it!

format_shapes

2. Wrong Format

If the output doesn't match the expected format, the LLM may have gotten confused somewhere. Don't try to fix it - just discard and resample.

Counter-intuitive insight: Don't try to "repair" malformed outputs! The formatting error is often a symptom of deeper confusion. It's cheaper and safer to just throw it away and ask again.

Why Red-Flagging Matters

The main benefit isn't reducing the overall error rate (though it does). It's reducing correlated errors - cases where the same mistake keeps appearing.

# Without red-flagging: Same wrong answer keeps appearing
Vote 1: [wrong answer] (too long, 2000 tokens)
Vote 2: [wrong answer] (wrong format)
Vote 3: [wrong answer] (similar confusion)
# The wrong answer might win the vote!

# With red-flagging: Bad responses discarded
Vote 1: [DISCARDED - too long]
Vote 2: [DISCARDED - wrong format]
Vote 3: [correct answer]
Vote 4: [correct answer]
Vote 5: [correct answer]
Correct answer wins!

Results: Solving the Impossible

The Test: Towers of Hanoi

  • Each step has a clear correct answer

  • State-of-the-art LLMs fail at just 5-6 disks (~31-63 steps)

Surprising Finding: Small Models Work!

You don't need expensive reasoning models!

GPT-4.1-mini ($1.60/M tokens) outperformed o3-mini ($4.40/M tokens) in expected cost:
  • GPT-4.1-mini: $3,500 expected cost
  • o3-mini: $9,400 expected cost
  • Claude Haiku 4.5: $71,200 expected cost

When each step is tiny enough, a small focused model beats a large reasoning model!

Convergence to Solution

The voting process shows sharp exponential convergence:

  • After 3 voting rounds: ~18,000 steps still undecided
  • After 6 voting rounds: ~100 steps still undecided
  • After 10 voting rounds: ~2 steps still undecided
  • After 18 voting rounds: 0 steps undecided, 0 errors

Why This Matters

A New Paradigm for AI Scaling

Instead of building bigger and smarter single models, we can build swarms of simple models that together achieve superhuman reliability.

trending_up Old Scaling Paradigm

  • Bigger models = better results
  • More training = smarter AI
  • Single agent handles everything
  • Expensive and energy-intensive
  • Black box, hard to control

hub MDAP Paradigm

  • Many small models = reliable results
  • Decomposition = better performance
  • Microagents with focused roles
  • Cheaper, more efficient
  • Transparent, auditable

Parallels with Microservices

architecture Software Architecture Analogy

Just as microservices revolutionized software development by breaking monolithic apps into small, focused services, microagents can revolutionize AI by breaking complex tasks into small, focused agents.

Benefits include: modularity, independent scaling, easier testing, design for failure, and evolutionary improvement.

Safety Implications

Safer AI through decomposition:
  • Sandboxing: Each microagent has limited scope and power
  • Auditing: Every step can be logged and reviewed
  • Control: Easier to monitor and correct small agents
  • No collusion: Independent agents can't coordinate harmful actions
  • Smaller models: Less risk of emergent dangerous behaviors

Future Directions

The paper identifies several exciting research directions:

  • Automatic decomposition: Having AI discover optimal task breakdowns
  • Handling insights: Extending to creative/planning tasks, not just execution
  • Better decorrelation: More sophisticated methods to prevent correlated errors
  • Diverse agents: Using different models for different types of steps

Glossary

MDAP (Massively Decomposed Agentic Process)
A framework for breaking large AI tasks into millions of tiny subtasks, each handled by a focused microagent with error correction.
MAKER
The specific implementation: Maximal Agentic decomposition + first-to-ahead-by-K Error correction + Red-flagging.
Microagent
A small AI agent focused on solving exactly one tiny subtask. Multiple microagents work together to solve large problems.
MAD (Maximal Agentic Decomposition)
Breaking a task into the smallest possible subtasks, where each agent handles exactly one step.
First-to-ahead-by-k Voting
A voting scheme where sampling continues until one answer has k more votes than any alternative.
Red-Flagging
Detecting and discarding responses that show signs of unreliability (too long, wrong format) before they can influence voting.
Correlated Errors
Errors that tend to appear together - the same mistake repeated across multiple samples, which can defeat voting.
Towers of Hanoi
A classic puzzle used as the benchmark. Moving 20 disks requires over 1 million steps, each of which must be correct.
Multi-Agent Advantage
When a multi-agent system can solve problems that no single agent could solve alone (analogous to quantum advantage).
Error Correction
Techniques for detecting and fixing errors, borrowed from digital communication and quantum computing.
stars

Key Takeaways

  1. Million-step AI tasks are solvable with zero errors - something previously thought impossible.
  2. Extreme decomposition enables error correction - break tasks into the tiniest pieces.
  3. Voting works - simple majority voting with k=3 margin is enough for million-step tasks.
  4. Small models beat big models - when tasks are decomposed, cheap models outperform expensive reasoning models.
  5. Red-flagging prevents correlated errors - discard suspicious responses, don't try to fix them.
  6. A new scaling paradigm - instead of bigger models, use swarms of focused microagents.
